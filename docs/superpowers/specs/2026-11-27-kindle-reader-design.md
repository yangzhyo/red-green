# 在 Kindle Paperwhite（第 10 代）上阅读当前会话

Kindle 使用独立的 `/kindle` 阅读页，Supernote Nomad 继续使用现有阅读页。两端共用 Mac 上的局域网服务、设备配对和会话来源。[需求与实机照片 #40](https://github.com/yangzhyo/red-green/issues/40)

## 设计依据

实机已经显示 red-green 标题和首页静态文字「正在连接 Mac…」。现有页面需要启动 JavaScript 模块才能进入配对。本地对照中，跳过模块入口、Canvas 绘制失败和缺少 Intl 均能产生相同画面。Kindle 实际在哪一步中断仍待测量。[启动流程和对照实验](https://github.com/yangzhyo/red-green/issues/40#issuecomment-7197975785)

局部修补现有页的维护成本较低，但修通启动流程后，仍需为 6 英寸屏幕重新安排正文、导航和更新行为。只改响应式样式也保留了首屏对模块启动的依赖。独立页面增加了一套前端验收工作，换来可单独调整的排版、分页和脚本开销。分开适配的边界设在 HTML 与浏览器交互层。

## 从书签到正文

- 原首页的静态 HTML 提供「Kindle 阅读」链接。`/kindle` 可直接收藏。未配对时，Mac 返回可直接输入六位码的表单。配对成功后跳转到会话列表，刷新时只重取页面。
- 列表用单栏显示可读会话，标明项目与来源；同项目的多个会话可以区分。空列表显示等待提示和刷新链接。点会话名称打开正文。
- 正文显示「你」「助手」，保留段落、代码缩进和换行。长行在屏内折行。上一屏、下一屏、返回列表均使用普通链接。没有新内容时，点击「查看最新」仍可手动刷新。
- Mac 每页返回一轮完整对话，同轮的问题、补充文字和答复按原顺序展示。长文、表格和代码在页内滚动。点正文左半屏向上滚一屏，右半屏向下滚一屏，两屏重叠约一行。正文单指左滑切到下一轮，右滑切到上一轮，底部的上一屏、下一屏也可换轮。正文导航固定在屏幕底部并右对齐，翻页、查看最新、返回列表同排同样式，首尾不可用的方向仍占原位。Mac 授权后，当前 Codex 会话在「上一屏」前提供「回复」入口。原生表单提交成功后跳到最新正文。
- 自动更新由小型传统脚本增强。在末尾阅读时跟随新内容；回看前文时保留位置，提供「有新消息」入口。同一条回复增长时按消息 ID 更新。断网时保留已显示的正文，并提供重试。无脚本时配对、选会话、翻页和手动更新均可用。

## Mac 服务

Kindle 的 HTML 处理器复用现有配对码交换、Cookie 签发和撤销逻辑，以及当前会话列表、消息排序和增量游标。每个浏览器用独立的一次性码配对，服务保留所有已配对设备的凭据摘要。Kindle 支持当前会话阅读及授权后的 Codex 回复，Nomad 另提供历史与继续对话功能。

Kindle 配对使用专用表单 POST，六位码仅放在请求体。表单使用与页面绑定的短期随机值校验提交来源，再调用现有配对码交换。现有 JSON 配对入口继续执行原有校验。每次读取列表、正文和增量前校验设备 Cookie，慢读取返回前再次核对授权。沿用禁止缓存和现有正文转义规则。

## 验收

1. 在禁用 JavaScript 的浏览器从原首页进入 Kindle 页，验证错码、有效码、刷新后沿用配对、打开会话、前后翻页和手动更新。撤销后，直接访问已收藏的正文地址也应要求配对。
2. 用现有样本服务在第 10 代 Paperwhite 真机验证长回复与长代码行。逐页核对内容连续、按钮可点、正文无需横向拖动。检查长表首尾同页及底部导航位置。
3. 在真机正文末尾等待样本追加，再回翻至有明显标记的一段等待下一次追加。分别核对自动跟随、原位停留和跳到最新。断网后恢复，确认同一回复连续且内容未重复。
4. 给 Nomad 生成另一个配对码。从两台设备各自的入口往返打开正文，确认先配对的设备仍可阅读。

2026-11-27 真机反馈确认，Kindle 可以轻点滚动、横滑换轮，并已从 Kindle 发出 Codex 回复。多设备更新后，用户确认 Kindle 与 Nomad 可切换使用。[多设备配对 #47](https://github.com/yangzhyo/red-green/issues/47)
