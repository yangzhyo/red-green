# 在 Supernote Nomad 上阅读会话

[需求 #27](https://github.com/yangzhyo/red-green/issues/27) · 首版设计已确认

## 阅读入口

用户希望在 Supernote Nomad（A6 X2）上回看本机 CLI 会话的提问和回复，放下笔也能读到后续对话。已确认由读者在 Nomad 上选择会话。正常使用时，Mac 运行 red-green，两台设备连接可互访的同一 Wi-Fi，Nomad 的阅读页处于前台。

首次使用时，用户在 Mac 上开启局域网阅读，将显示的固定地址存为 Nomad 笔记里的「读会话」网页链接，并可把这一页加入侧栏快捷访问。下次从同一入口进入。默认关闭共享；开启时明确说明配对设备能读取下述会话。首次连接输入 Mac 显示的一次性短码，成功后在该设备保存可撤销的凭据；入口地址本身不授予阅读权限。Mac 可关闭共享或解除配对。仅在用户信任的局域网内使用。

会话列表只列出 red-green 当前识别、且来源能提供正文的本机 Claude Code 和 Codex CLI 会话。配对后，零个会话时显示「等待可读会话」并自动检查；首次出现唯一会话时直接进入；多个时用项目名、来源和简短会话标识区分。在正文页可以主动回到列表，即使列表只有一项也能留在那里。新会话出现时不抢走已打开的正文。结束后保留本页已加载的文字供回看，提示「会话已结束」，回到列表后不再列出。

## 阅读和自动刷新

竖屏单栏、白底黑字，用「你」「助手」标出发言人，保留段落、列表、换行和代码缩进，长行在屏内折行。阅读页提供可点按的上一屏、下一屏，长回复可分屏连续读完。

    ‹ 会话列表                 red-green · Codex
    你
    为什么回看时会跳到底部？

    助手
    新回复到了。我们可以先记住你读到的这一段……

    上一屏             有新消息 ↓             下一屏

- 打开会话时定位到最新一屏。在末尾时跟随新内容，前台每 3 秒检查一次可读正文的变化，作为首版试验值。合并同一次检查内的更新，同一回复继续增长时更新原消息。来源一次交付整条回复时整条显示。没有变化时保持页面静止。
- 主动翻回前文后，以首个可见消息及其段落位置为锚点。新内容到达只显示「有新消息」，继续翻页仍从原位置阅读。点提示或主动翻到末尾恢复跟随。补载较早消息时也保持当前段落的位置。
- 网络中断时保留已显示的正文，提示正在重连。恢复网络或设备唤醒时立即检查更新。原会话仍可读时，根据最后一次确认的位置补齐漏看的内容，保持断开前的阅读模式。
- 若离线期间 CLI 已退出，首版只保留当前页已加载的文字，提示「会话已结束，离线期间可能还有未同步的消息」。Mac 收到明确结束事件时才报告结束。来源断线或一次列表查询缺失时提示「会话暂不可用」，继续重试。

## Mac 如何提供正文

沿用当前会话发现机制，以来源和会话 ID 定位。局域网阅读服务独立按需取正文，现有桌面状态轮询保持原频率。返回正文前校验阅读凭据及当前可读会话。阅读操作只读，不触发终端聚焦、宠物已阅、发送消息或审批。

- **Claude Code**。现有钩子写入的 `detail` 最多 300 字。设计建议在事件提供会话记录位置时，于本机登记会话 ID 和该位置，独立读取记录中的用户、助手文本。先用受控样本验证普通回复、工具回合、多段文本和会话恢复。对缺少映射的旧会话，在后续事件补齐后自动出现；映射采集须覆盖现有「运行中」事件提前退出路径。
- **Codex CLI**。沿用本机 App Server 和已识别的线程 ID。现有观察器只取最近一个回合的摘要。阅读服务另行按页读取所选线程的正文，先验证当前 CLI 在进行中和完成后分别能提供哪些文本、分页标识及顺序；不恢复线程。来源暂时返回空数据时保留上一次成功读取的内容。
- **两种来源共用的约定**。服务端只投影面向读者的用户和助手文字，同一条回复使用稳定标识；忽略工具输入输出、内部指令和推理。初次取最近一批，向前翻时分批取更早正文，向后同步时返回新增或改写的消息。客户端去重，过期游标触发重新对齐。页面始终按文字处理会话内容，禁止执行其中的脚本。客户端只传会话标识和游标，本机文件路径、终端和控制接口均不对外提供。

## 方案取舍和验证顺序

首选 Mac 提供只读网页，Nomad 的固定链接既可直达唯一会话，也可打开会话列表。另一种做法是在 Mac 指定要显示的会话，设备端更简单，但每次换项目都要操作 Mac。专用 Android 阅读应用可以直接控制分页和前后台恢复，需要额外安装维护；只有内置网页入口无法满足真机验证时，才重新讨论设备端载体。

Supernote 文档确认笔记支持网页链接，笔记页可加入快捷访问。局域网地址、前台脚本执行、配对凭据持久性及唤醒行为仍需在 Nomad 上实测。先用无私人内容的两轮样本文字走通固定链接、配对、自动追加、翻页和唤醒，再接入真实会话。地址需要在同一网络中可重复打开，优先实测稳定主机名；若设备不能解析，在 Mac 展示局域网地址，并说明地址变化时如何更新笔记。[网页链接](https://support.supernote.com/en_US/inserting-links-to-notebooks) · [快捷访问](https://support.supernote.com/favorites-and-quick-access)

## 验收

1. 在 Nomad 笔记中点已保存的入口，首次配对后可重复进入。未配对或被撤销的客户端读不到列表和正文。
2. 分别验证零个、一个和多个可读会话。两个同项目的会话能区分，选定一个后，另一会话的更新不会出现在当前页面。
3. 对两种来源各打开一个多轮会话，逐屏回看并与终端核对角色、顺序、多段中文和跨屏代码。工具回合之后仍能看到对应的回复。
4. 在末尾停留并从终端继续一轮，来源已提供的新文字在正常局域网下以 5 秒内可见为初始目标，无需点按。正文静止一分钟时页面无周期性重绘。
5. 在较早段落停留，连续追加两轮，当前段落留在原位；点「有新消息」后回到末尾，能顺序读到新增内容。
6. 断网或休眠期间追加一轮，保持原会话可读。恢复后自动补齐，消息无重复，回看位置不丢失。另测离线期间追加一轮后退出 CLI，确认页面保留已读内容，并按来源能确认的状态提示。Mac 端的宠物状态与终端交互保持原有行为。

首版采用上述配对方式和活跃会话范围。已确认以 3 秒为前台检查间隔，5 秒为首次真机验收目标。真机验证时记录固件版本、来源版本和实际延迟，再定验收阈值。分页批量、游标编码和具体排版尺寸交由实现时按设备可视区域决定。
