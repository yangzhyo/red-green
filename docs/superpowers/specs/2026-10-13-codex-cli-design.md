# #16：Codex CLI 会话与账号用量接入设计

关联需求：[支持 Codex CLI](https://github.com/yangzhyo/red-green/issues/16)。

状态：接入方式验证中。用户已授权开始处理需求；专用启动器尚未获确认，不作为实施前提。

2026-10-16 修正：优先验证安装集成后继续直接运行 `codex` 的方式，与现有 Claude Code 使用习惯一致。此前只读探针证明了查询接口缺少 tty，尚未实测原生 Hook 的进程树和环境，也未证明无启动器方案不可行。下文启动器和通信代理的细节保留为备选设计；共通功能与验收要求仍然有效。

## 目标与边界

让本机 Codex CLI 会话拥有与 Claude Code 相同的桌面宠物体验：会话独立、名牌稳定、状态可感知、点击回到正确终端、已阅和前台静默生效。Codex CLI 账号用量属于本期范围，需要显示已用比例与重置时刻，并与 Claude Code 用量明确区分。

继续使用 macOS、Tauri 2、窗口即宠物、manager 裁决展示状态的架构。既有 Claude Code hooks 和 status line 保持兼容。实现、验证在本地完成；交付 PR，合并另按仓库规定由用户决定。

首版兼容基线是本机已验证的 Codex CLI 0.162.1。更早版本不声称兼容；新版本通过协议能力检测和明确的错误提示处理，不把无法读取的信息伪装成正常数据。

## 已验证的接口

2026-10-13 使用本机 `codex-cli 0.162.1` 生成 JSON Schema，并通过本机后台服务的 Unix socket 做了只读请求：

- `initialize` 握手成功。
- `account/rateLimits/read` 实际返回账号标识，以及 300 分钟、10080 分钟两个窗口的 `usedPercent`、`resetsAt`。
- `thread/loaded/list` 和 `thread/read` 能读取已加载会话及运行状态。
- 控制 socket 使用标准 WebSocket 握手；`codex app-server proxy` 是字节代理，不能直接向其输入 JSONL。
- 会话查询协议没有提供宿主终端 tty。会话的 `source` 还可能保留创建来源，不能仅靠它判定当前是否由 CLI 打开。

官方文档另外确认了原生 CLI 可以通过 `--remote unix://PATH` 连接 App Server；结构化事件包含回合开始、完成、失败、等待审批和等待输入。以上只读验证没有启动模型任务、修改配置或接管任何现有会话。

## 接入方式比较

1. **原生 Hooks 配合只读后台查询（优先验证）**：最接近现有 Claude Code 集成，能覆盖大部分事件。默认后台服务可能使 Hook 进程脱离终端进程树，这是待实测的风险；文档没有直接等价于 Claude Code `StopFailure` 的事件，需要验证后台查询能否补齐。缺少某一事件不能直接推出必须修改启动方式。
2. **仅轮询后台服务或解析会话日志**：已核实的会话查询接口不提供 tty，因此仅凭它不足以绑定同目录的多个终端会话；官方明确说明 transcript 格式不稳定。
3. **原生 CLI 的本地通信代理（备选）**：由专用启动命令记录 tty，并在该 CLI 与本机后台服务之间转发原生 WebSocket 消息。预期可直接观察该终端收发的状态，但完整通信与交互兼容性尚未实测。

下一步先验证第 1 种：原生 CLI 启动、恢复、双会话及退出时的 Hook 输入、环境和进程树；审批、失败与主动中断能否通过 Hooks 和只读接口组合准确识别。只有明确发现无法补齐的关键能力，再讨论第 3 种及其使用成本。账号用量已能通过独立只读接口取得，本身不构成增加启动器的理由。

## 备选启动器的用户流程

安装后提供 `red-green-codex`，调用的仍是已安装的原生 Codex CLI。启动器不替换 `codex` 可执行文件，不修改 shell 配置，不代替用户处理审批。

新会话、`resume`、`fork` 是本期交互入口；模型、目录、profile 等常用参数需要在真实 CLI 验证中确认保持原行为。登录、升级等管理子命令直接交给原生 CLI。远程主机、`--no-daemon` 和用户自定义 `--remote` 不能误接到本机观测链路，遇到这些参数明确说明本期支持边界。

首次安装前已经打开的 CLI 会话不自动绑定终端；用户从新入口启动或恢复后接入。无需重新登录，也不读取或复制账号凭据。

## 备选代理的数据流与模块边界

- **启动器**：在终端前台运行，记录准确 tty、进程身份和独立实例标识；创建仅当前用户可访问的短路径 Unix socket，连接该 Codex 配置目录对应的本机后台服务，再启动原生 CLI。进程退出或信号到来时，清理自己创建的 socket 和状态。
- **通信代理**：使用维护中的 WebSocket 库转发消息，保留请求 ID、参数、响应和原有顺序。状态采集失败不能替用户批准、拒绝或改变工具调用。断开时清理自身资源；不停止共享后台服务，不归档或删除用户会话。
- **Codex 适配器**：观察会话响应及事件，产出既有会话模型；独立读取账号用量。宠物应用不直接解析 Codex 协议，也不轮询 transcript。
- **文件读取层**：继续读取 Claude Code 的原有目录；额外读取 red-green 自有的 Codex 数据目录。会话和用量分目录，原子写入，窗口身份带来源命名空间。
- **manager 与渲染器**：复用皮肤、叫声、已阅和前台静默；用量按来源及账号组织，再交给用量表。宠物仍按项目确定皮肤，名牌保留项目名，并能辨识 CLI 来源。

启动器放在现有 Rust 工程中，通过应用可执行文件的专用入口运行，安装一个薄 shell 启动脚本；避免引入额外的常驻 Node 服务。代理所需的异步和 WebSocket 依赖单独显式声明。

## 会话身份和生命周期

以来源和 Codex thread ID 区分会话；不能按 cwd 或项目名合并。相同目录中多个 Codex 会话及 Claude Code 会话必须共存。

启动器记录 tty，状态事件提供 thread ID，两者在同一 CLI 连接内绑定，不按项目目录猜测。恢复既有会话沿用 thread ID；项目名首见后锚定。子代理事件不额外创建宠物，也不能覆盖主会话状态。

会话正常退出、CLI 连接关闭后，对应宠物离场；异常退出通过进程身份检查排除残留文件。进程身份包含启动信息，不能只凭可复用的 PID 判断存活。只读端忽略失效记录，文件清理由写入端负责。

## 状态映射

| Codex 信号 | 会话状态 | 展示规则 |
| --- | --- | --- |
| 新建或恢复、当前没有回合 | 空闲 | 首见静默采纳 |
| 回合开始或 active 且无等待标记 | 运行中 | 不叫 |
| waitingOnApproval / waitingOnUserInput，或回合中的审批与结构化输入请求 | 待确认 | 等待解除后回运行中；不响应审批请求 |
| 回合正常结束、末条答复为问句 | 轮到你 | 复用现有末行问句启发式；已阅不解除 |
| 回合正常结束、未命中问句 | 已完成 | 可由已阅转为空闲 |
| 回合 failed / 会话 systemError | 异常中止 | 可由已阅转为空闲 |
| 用户主动中断回合 | 空闲 | 不误报为外部错误，不播放异常叫声 |
| CLI 退出或离开该会话 | 离场 | 删除该连接拥有的会话展示 |

只根据明确的回合结果判定完成或失败；可重试错误、工具自身执行失败不能直接变成“异常中止”。回合终态之后的 idle 通知不能覆盖已完成或轮到你。恢复会话和补发消息不能重放旧叫声。

若 CLI 协议能力不符合基线，给出可诊断的错误，不静默伪造状态。

## 账号用量

通过只读 `account/rateLimits/read` 获取快照；有活动 Codex CLI 时启动读取，每 60 秒刷新，并在账号变更后重新读取。多个同账号会话共享一份采集结果，避免逐会话请求。

保留账号身份、`limitId`、窗口时长、已用比例、重置时刻和采集时间。优先读取 `rateLimitsByLimitId`，仅在它缺席时兼容单一 `rateLimits`。不同 limitId 不能相加，也不能把不同窗口强行标成五小时或七天。

用量表提供明确的 Claude Code / Codex 标识，两个来源各自显示；静置双环对应所选额度组的两个窗口，悬停显示其实际时长、比例和重置时刻。多个额度组或账号在明细中分组，默认概览选择 Codex 的 `codex` 额度组，不混算、不为每只宠物重复展示。

Codex 用量过期、窗口缺失、API 计费或暂时读取失败时，显示未知或暂不可用，不显示成零。刷新失败可短暂保留最近成功数据并标记更新时间，超过两个刷新周期则不再作为当前百分比展示。账号变化立即丢弃旧账号的当前视图。Claude Code 的既有过期规则保持兼容。

账号用量不进入宠物状态机，不触发叫声。用量表的来源标识、展开明细、窗口尺寸和宠物间距必须一起验证，避免内容裁切或透明窗口抢占邻居点击。

## 安装与文档

安装步骤检查 Codex 版本、应用可执行文件和命令路径；重复安装不覆盖用户的 Codex 配置、Hooks 或其他命令。尊重 `CODEX_HOME`，路径含空格时仍可运行。数据目录采用 red-green 自有路径，并提供测试目录覆盖项，验证不污染真实状态文件。

更新 README、领域词汇、状态文件协议和一条架构决策，写明入口、支持版本、真实数据来源、首版边界以及卸载方式。领域术语中“会话”“用量”由 Claude Code 专属扩展为按来源区分。

## 验证与完成条件

测试优先放在“Codex 事件输入 → 状态与用量文件 → 展示模型”这一边界，使用协议样本及临时目录验证外部行为。

- 同目录双会话、来源间相同原始 ID、恢复会话、子代理事件、退出及异常残留。
- 六个状态、等待解除、问句末行、用户中断、可重试错误、回合失败，以及事件补发与顺序。
- 两种来源、同账号多会话、账号切换、多额度组、非五小时窗口、缺失和过期数据、刷新失败。
- 原生通信请求与响应完整转发；审批仍由 CLI 展示和处理；代理采集失败不改变业务结果。
- 按仓库 `/verify` 注入假会话和用量，观察宠物窗口、叫声、已阅、前台静默和用量表。
- 真实 Codex CLI 验证启动、输入、完成、审批、恢复、退出，以及 Terminal / Ghostty / tmux 的点击聚焦。
- 执行 Rust 测试、JS 测试及 CI 原有语法检查和 `cargo check`；开 PR 后完成双轴审查并记录评审小结，等待 CI 通过。

只读接口探针已经通过；代理、原生 CLI 交互和界面尚未实现或验证，不能把探针结果作为功能完成的证据。
