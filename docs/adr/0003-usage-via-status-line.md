# 用量走 status line 旁路，显示在一枚共用的用量表上

账号用量（五小时 / 七天窗口的已用比例与重置时刻）只出现在 Claude Code 交给 status line 命令的 JSON 里（`rate_limits`），hooks 事件、OTel 指标、本地文件都没有。所以新增 `statusline/usage.sh` 作为 hooks 之外唯一的写入通路：把用量写进 hooks 同一个目录的 `usage.json`，复用同一个 watcher，保持「脚本只写、app 只读」的单向数据流。status line 只有一个槽位，用户已有自己的 status line 时不覆盖，只提示串接。

显示上，用量属于账号而不属于会话，于是不挂在每只宠物身上，而是一枚独立小窗的**用量表**，全列共用一份：静置是像素圆表（双环 + 圆心数字），悬停展开明细。代价是多了一个窗口和一份布局常量，换来的是宠物本身保持干净，多会话时不重复。

## Considered Options

- 每只宠物名牌下各画两行用量：实现过，多只宠物时重复啰嗦、每只三根条太重，被否。
- 菜单栏项（tray）：账号级状态放在系统状态区最顺手，但离宠物远、脱离像素世界，用户选了留在宠物列里的共用物件。
- 解析终端 `/usage` 的文本输出：交互式命令，没有机器可读形式，被否。
